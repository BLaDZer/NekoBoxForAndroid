What the draft got right

- Pin: sing-box is pinned to exactly v1.14.4, which is the latest stable release. The newer tags are all 1.15 alphas.
- Compile and tidy: libcore builds, go vet and the tests pass, and go mod tidy is clean.
- Android side: the Kotlin ConfigBuilder, the WireGuard endpoint, the new-style DNS servers and the rule actions are consistent with 1.14. NativeInterface.kt implements the new interface-monitor methods.
- Interface binding: dropping dialer.DoNotSelectInterface is fine. Sockets are still protected through UsePlatformAutoDetectInterfaceControl.

What I fixed

- Context leak: in box.go, NewSingBoxInstance leaked its context when config parsing failed.
- Silent deprecations: deprecation notes from sing-box were being dropped silently, because no manager was registered. I added deprecated_box.go, which logs them and never aborts. I avoided sing-box's stderr manager on purpose, because it calls Fatal on features about to be removed and that would kill the service.
- Hardcoded version: I removed the patch that hardcoded the version string. The version now comes from an ldflag (1.14.4-neko), so there is one less patch to refresh on each update.

Check script

Run it with ./run lib core check. Add --android to also cross-compile for android/arm64, which needs the NDK. Add --quick to skip the sing-box package tests. It needs only Go and prints a PASS/FAIL summary. It covers:
- submodules and patches
- go.mod tidy
- host build and vet
- tests
- the sing-box tests for the patched packages

The tests include libcore/config_compat_test.go, which loads configs shaped like the app's output (libc real sing-box core. I confirmed it fails on a removed outbound type. It reports two deprecations theapp still uses:
- independent_cache: the app still sets this DNS option.
- Per-outbound domain_strategy: the app still sets this on outbounds.

Both stop working in 1.16, not now.

Submodule setup

- Submodules: sing-box, libneko and gomobile now live in libcore/third_party/, and the go.mod replaces point there.
- Patches: the four Neko patches are applied only to the working tree. The submodule pointer always stays on pristine upstream.
- Update command: ./run lib core update [tag] reverts the patches, checks out the new ref, applies the patches, runs go mod tidy, and runs the check.
- CI: the CI workflows now check out submodules and use status.sh for the cache key.

I tried update against v1.15.0-alpha.13 as a test and rolled back. It flagged three breakages:
- the missing CreateAutoRedirect method
- the AndroidPackageNames rename
- a type change in geoip.go

That test also exposed a bug in my own script (the submodule init failed on a patched checkout), which I fixed.
